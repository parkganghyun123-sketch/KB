# TradeGuard UI/UX 벤치마킹 & 차별화 설계
> 2026-07-28 · 작성 관점: 서비스 기획(PO) + UI/UX
> 목적: 경쟁 2팀 때문에 축소한 기능을 **되살리되, 우리 강점 안으로 흡수**한다

---

## 0. 이 문서의 출발점

D1에 경쟁작 분석 후 환노출 기능을 "부가 분석"으로 강등했다. 그런데 **기능을 숨기는 건 차별화가 아니다.**
올바른 해법은 이것이다:

> **경쟁팀은 환율만 본다. 우리는 "서류 하자 → 대금 지연 → 그만큼 늘어난 환노출"을 하나로 잇는다.**

즉 환율 조절 기능을 되살리되, **하자 판정 결과와 연결**해서 경쟁팀이 못 하는 화면을 만든다.

---

## 1. 벤치마킹 — 경쟁 서비스 4종

### ① Traydstream (영국, 글로벌 은행 도입)
무역서류 자동 심사의 사실상 표준. 30만 개 이상의 룰 변형으로 UCP600·ISBP를 검증한다.

| 항목 | 내용 |
|---|---|
| 핵심 UI/UX | 은행 심사역용 워크벤치. 좌: 서류 뷰어, 우: 룰 체크리스트. 하자별 룰 ID 표시 |
| 호평받는 기능 | 서류 간 교차검증 · 중앙 감사추적(auditability) · OCR로 종이서류 디지털화 |
| **페인 포인트** | **은행 전용 B2B** — 수출기업이 직접 못 씀 · 도입 비용·기간 큼 · 화면이 전문가 전제라 학습곡선 가파름 |

### ② Bolero / essDOCS (전자 선하증권·서류 유통)
서류를 "만들고 주고받는" 플랫폼.

| 항목 | 내용 |
|---|---|
| 핵심 UI/UX | 거래 단위 워크스페이스. 서류 상태(작성→서명→전송) 파이프라인 시각화 |
| 호평받는 기능 | eB/L 법적 효력 · 당사자 간 실시간 상태 공유 |
| **페인 포인트** | **"틀렸는지"는 안 알려준다.** 유통은 되지만 하자 판정 기능 부재 · 상대방도 가입해야 함(양면 시장 문제) |

### ③ uTradeHub (한국 국가전자무역플랫폼)
국내 수출입 기업 대부분이 쓰는 공식 창구. 2.0에서 스마트 무역장부·전자문서 유통이 추가됐다.

| 항목 | 내용 |
|---|---|
| 핵심 UI/UX | 업무별 메뉴 트리(신용장/통관/물류…) · 폼 입력 중심 |
| 호평받는 기능 | 은행·관세청 연계 · 전자문서 즉시 유통 |
| **페인 포인트** | **메뉴가 깊고 용어가 어렵다** — 전담 인력 없는 중소기업엔 진입장벽 · 서류를 "제출"할 뿐 **사전 검증은 없음** · 학술 연구에서도 중소기업 활용도 저조가 반복 지적 |

### ④ 은행 창구/이메일 (현행 실무의 실체)
사실상 가장 큰 경쟁자는 **"그냥 은행에 내보고 까이면 고치는" 현재 방식**이다.

| 항목 | 내용 |
|---|---|
| 핵심 UX | 서류 제출 → 은행 심사역 검토 → 하자 통보(전화·메일) → 수정 → 재제출 |
| **페인 포인트** | **피드백까지 1~3영업일** · 하자 사유가 구두라 기록이 안 남음 · 반복 실수 학습 불가 · 그 사이 환율·기일이 흘러감 |

### ⑤ 대회 내 경쟁 2팀 (참고)
| 팀 | 본체 | 우리와의 관계 |
|---|---|---|
| KB 환부장 | 환리스크 관리 | 서류 검증 없음 |
| TradePilot FX | 결제일 기반 자연헤지·손실한도 | 서류 검증 없음 |

## 2. 페인 포인트 종합 → 우리가 파고들 틈

| # | 시장 공통 페인 포인트 | 우리 대응 |
|---|---|---|
| P1 | **판정 도구는 은행만 쓴다** (Traydstream) | 수출기업이 직접 쓰는 셀프체크 |
| P2 | **유통은 되는데 검증이 없다** (Bolero, uTradeHub) | 제출 전 사전 검증 |
| P3 | **하자 사유가 기록으로 안 남는다** (은행 실무) | 조항 인용 + PDF 리포트 |
| P4 | **전문 용어 장벽** (uTradeHub) | 하자마다 "왜 문제인지" 한국어 한 문장 + 수정 문구 |
| P5 | **서류 문제와 자금 문제가 따로 논다** | **하자로 인한 지연이 환노출을 키운다는 연결** ← 아무도 안 함 |

> **P5가 우리만의 자리다.** 경쟁 2팀은 환율만, Traydstream은 서류만 본다.
> 둘을 잇는 화면은 시장에 없다.

## 3. 차별화 UI/UX 컨셉

### 컨셉 한 줄
> **"하자 하나가 며칠을 미루고, 그 며칠이 얼마를 흔드는지 한 화면에서 보여준다."**

### 신규 편의기능 5가지

#### F1. 하자→지연→환노출 연결 시뮬레이터 ★ 핵심 차별화
하자 심각도에 따라 **예상 지연 일수**를 산출하고, 그만큼 늘어난 **환율 노출 기간**을 계산한다.

```
HIGH 하자 1건  → 서류 재작성·재제시 예상 +5~10영업일
                → 수취일이 8/12 → 8/24로 밀림
                → 그 기간 환율 변동에 노출되는 금액 USD 84,000
                → 변동폭 ±5% 가정 시 원화 수령액 ±610만원 변동
```

**왜 차별화인가:** 경쟁팀은 "환율이 흔들리면 얼마 손해"까지만 간다.
우리는 **"당신 서류의 이 하자 때문에 노출 기간이 늘어난다"** 는 인과를 보여준다.
서류 검증을 안 하는 팀은 이 화면을 만들 수 없다.

#### F2. 환율 시나리오 조절 (복원 + 강화)
기존 슬라이더를 되살리되, **지연 일수 슬라이더를 추가**한다.

- 환율 변동폭 슬라이더 (±1~10%)
- **지연 일수 슬라이더 (0~30일)** ← 신규
- 기준 환율 수동 조정 (기본값은 ECOS 실값)

#### F3. 수정 체크리스트 (Fix-it Checklist)
하자 목록을 **행동 목록**으로 전환한다. 각 항목에 체크박스 + 담당자(우리/운송사/개설의뢰인) + 소요 예상.

> uTradeHub·Traydstream 모두 "문제 목록"에서 끝난다. **"그래서 뭘 하면 되는가"** 를 주는 곳이 없다.

#### F4. 하자 근거 원본 즉시 확인
하자 카드에서 해당 서류의 원본 이미지를 바로 펼쳐 본다. 심사위원의 "진짜 읽은 거 맞아?"에 대한 즉답.

#### F5. 반복 실수 리포트 (백로그)
같은 기업이 반복하는 하자 유형을 누적 집계. 이번 대회 범위 밖이나 **사업화 스토리**로 제시.

## 4. 정보 구조(IA)

```
TradeGuard
├─ ① 서류 등록        진입점 · 샘플/업로드 2모드
├─ ② 판독 결과        추출 필드 ↔ 원본 대조 · 신뢰도
├─ ③ 하자 리포트  ★  등급 · 하자 카드 · 조항 인용 · 수정 체크리스트
└─ ④ 영향 분석        하자→지연→환노출 연결 · 시나리오 조절 · KB 상품
```

현재 앱은 **단일 페이지 스크롤**로 ①~④를 순차 노출한다(탭 아님).
이유: 8일 개발 제약 + 데모에서 화면 전환 없이 한 번에 보여주는 게 유리.

## 7. 발표 문장

> "무역서류 심사 솔루션은 은행용이고, 환리스크 도구는 자금팀용입니다.
> 둘 사이가 비어 있습니다 — **서류의 하자가 대금 수취를 며칠 미루고, 그 며칠이 환율에 노출된다**는
> 연결을 보는 도구가 없습니다. TradeGuard는 그 연결을 한 화면에 넣었습니다."
