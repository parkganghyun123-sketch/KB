## A-9. 서류 자기모순 2건 — **최우선, 오늘 안에**

### 무슨 일인가

`DEFECT-017`·`DEFECT-018`은 정답 라벨이 **"본선적재 표기 없음(`BL_NO_ONBOARD_NOTATION`)"** 인데,
렌더링된 B/L에는 **`CLEAN ON BOARD`가 인쇄돼 있습니다.**

```
DEFECT-017  clean=True  shipped_on_board={'indicated': False, 'date': None, 'method': None}
DEFECT-018  clean=True  shipped_on_board={'indicated': False, 'date': None, 'method': None}
```

### 왜 결함인가

`CLEAN ON BOARD`는 실무상 **무사고 본선적재**를 뜻합니다. 그 문구가 찍힌 B/L을 두고
"본선적재 표기가 없다"고 하는 건 서류 자체가 앞뒤가 안 맞는 것입니다.
**A가 계속 찾아온 우발 하자와 정확히 같은 유형**입니다.

### 원인 위치

`benchmark/generate_cases.py` **254행**

```python
"freight_terms": "COLLECT", "clean": True, "originals_count": 3,
```

`clean`이 **모든 B/L에 무조건 True로 고정**돼 있습니다. `BL_NO_ONBOARD_NOTATION` 하자를 주입해
`shipped_on_board.indicated = False`로 만들어도 `clean`은 True로 남고,
템플릿(`templates/bill_of_lading.html.j2` 82행)이 그대로 `CLEAN ON BOARD`를 찍습니다.

```jinja
{% if bl.clean %}<br><br>CLEAN ON BOARD{% endif %}
```

### 영향 — 종단 성능의 미탐 2건이 전부 이것입니다

`extracted/`를 보면 모델은 **서류를 정확히 읽었습니다.** `CLEAN ON BOARD`가 보이니
`shipped_on_board.indicated = True`로 판단했고, 그래서 하자를 못 잡았습니다.
**모델이 틀린 게 아니라 정답 라벨이 서류와 어긋난 것입니다.**

수정하면 (저장된 추출값 위에서 실측):

| | 현재 | A-9 수정 후 |
|---|---|---|
| 하자 검출 | TP 20 · FP 3 · **FN 2** | TP 22 · FP 3 · **FN 0** |
| F1 | 0.889 | **0.936** |
| 재현율 | 90.9% | **100%** |
| 등급 일치율 | 87.5% | **92.5%** |

### A에게 묻는 것

1. **`clean`의 의미를 어떻게 잡을 것인가.** 제 제안은 `clean = shipped_on_board.indicated`로 연동하는 것인데,
   실무상 *무사고(clean)* 와 *본선적재(on board)* 는 **별개 개념**입니다.
   - `CLEAN ON BOARD`(무사고 본선적재)
   - `CLEAN RECEIVED FOR SHIPMENT`(무사고 수취, 본선적재 전) ← 이쪽이 맞는 표현인지
   - 하자 주입 시 문구를 어떻게 바꿔야 실무에 맞는지 **A가 정해 주십시오.**
2. 이 2건 말고 **다른 하자 주입에도 같은 유형의 모순이 있는지** 훑어봐 주십시오.
   (예: 서명 하자를 주입했는데 서명란은 그대로인 경우 등)

> 수정은 A가 방향을 정해 주면 C가 반영해도 됩니다. **판단만 주셔도 됩니다.**

| `AMOUNT_EXCEEDS_LC` | 송장 금액을 신용장 한도로 낮춤 | 초과분을 **T/T로 분리**하는 게 더 일반적입니까? |
