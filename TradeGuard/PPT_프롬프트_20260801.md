## 0. 먼저 알아둘 것

**이 문서는 발표 자료가 아닙니다.** 심사위원이 **발표 없이 혼자 읽습니다.**
그래서 "키워드만 큰 글씨로" 스타일은 위험합니다 — 말로 채울 사람이 없으니 근거가 빈 것처럼 보입니다.
**슬라이드마다 문장이 완결돼 있어야** 합니다.

### 작업 순서

```
1) 아래 §1 프롬프트를 통째로 복사 → 감마에 붙여넣기 → 생성
2) §2 사진 12장을 캡처해서 해당 슬라이드에 교체 투입
3) §3 환각 체크리스트로 숫자 전수 대조   ← 이 단계 생략 금지
4) PDF로 내보내기 → 제출
```

**3번이 제일 중요합니다.** AI 슬라이드 툴은 빈칸을 그럴듯한 숫자로 메웁니다.
우리 프로젝트의 정체성이 "숫자를 부풀리지 않는다"인데 여기서 무너지면 전부 무의미해집니다.

시각자료: As-Is 업무 흐름을 3단 도식으로. [서류 작성] → [육안 대조] → [은행 제시 후 하자 통보]
하단 결론: 사람의 주의력에 의존하는 구간이 그대로 남아 있습니다.

[7장] 폐쇄 루프 ★차별점
제목: 하자를 알려주는 데서 멈추지 않습니다
본문:
· 하자마다 수정값을 제시합니다. 이 값은 신용장에 적힌 기대값에서 코드가 도출한 것으로, AI가 지어낸 문장이 아닙니다.
· 사용자가 승인한 항목만 반영해 재심사합니다.
· 재심사에는 LLM을 부르지 않으므로 즉시 끝나고 추가 비용이 없습니다.
· 무엇을 어떤 값으로 바꿨는지 감사 이력에 남습니다.
[사진③] 캡션: 수정 제안 — 승인할 항목 선택
[사진④] 캡션: 재심사 결과 — C등급에서 A등급, 제출 가능
[사진⑤] 캡션: 감사 이력 — 변경 항목 추적
하단 결론: 진단에서 끝나면 사용자의 일은 그대로 남습니다.

[8장] 창구 연결
제목: 서류 상태가 어느 창구로 갈지를 가릅니다
본문:
· 하자가 없으면 수출환어음 매입으로 바로 안내합니다.
· 하자가 있어도 치유 가능하면 수정 후 매입 경로를 안내합니다.
· 치유 불가한 하자는 하자 네고 또는 추심 전환으로 분기합니다.
· 재발행 지연이 생기면 그 기간의 자금 공백과 환위험에 대응하는 항목을 함께 보여줍니다.
· 안내하는 항목은 외국환은행의 고유 업무만 씁니다. 브랜드 서비스명이나 한시 우대 프로그램명은
  종료·개편될 수 있어 의도적으로 넣지 않았습니다.
[사진⑥] 캡션: 창구 연결 — 서류 상태에 따른 분기 안내
하단 결론: 진단 결과가 곧 다음 행동으로 이어집니다.

[9장] 아키텍처
제목: AI는 읽고, 코드가 판정합니다
시각자료: 아래 구조를 다이어그램으로 그려 주세요.
  [서류 이미지 3종] → [추출 · LLM · 교체 가능] → [판정 · 결정적 규칙 · LLM 없음]
   → [등급/근거] → [수정 제안 · 결정적] → [재심사 · 결정적] → [창구 연결]
  LLM 구간과 규칙 구간을 다른 색 박스로 뚜렷하게 나눠 주세요.
본문:
· LLM 호출은 판독 단계에만 국한됩니다. 서류 1장당 종류 판별 1회 + 필드 추출 1회, 총 2회입니다.
· 판정·수정 제안·재심사의 LLM 호출은 0회입니다. 전부 코드가 수행합니다.
· 판독 모델은 교체 가능하게 추상화했습니다. 온프레미스 모델로 바꿔도 판정부는 그대로입니다.
· 같은 서류는 언제 넣어도 같은 결과가 나옵니다.
하단 결론: 재현되지 않는 판정은 은행 업무에 쓸 수 없습니다.

[10장] 왜 나눴나
