> 소요 10분 · 비용 0원 (LLM 호출 없음)

```bash
cd ~/KB/TradeGuard
bash demo.sh
```

서류 렌더링 → 하자 리포트 생성 → 판독 화면 생성 → 환율 스냅샷 → 서버 기동까지 한 번에 처리합니다.

> 환율도 그날 시세로 바뀝니다. LLM 호출이 없어 비용은 0원입니다.

## 장면 3 — 하자 판정이 실제로 동작한다 ★ 핵심 (3분)

브라우저에서 **세 화면을 순서대로** 엽니다. 셋 다 `detect.py`의 실제 출력입니다.

### ① 정상 판정 — `live_CLEAN-017.html`
> **등급 A · 100점 · 하자 0건**

이 케이스는 **함정**입니다. 송장 금액이 신용장 금액보다 **7% 큽니다.** 단순 비교였다면 하자로 잡혔겠지만, 신용장 39A의 과부족 허용치가 ±10%라 UCP600 30(b)상 정상입니다.

> **말할 것:** "금액이 초과했는데도 정상으로 판정합니다. 규칙을 안다는 뜻입니다."

### ② 중위험 판정 — `live_DEFECT-019.html`
> **등급 C · 65점 · 하자 2건 (HIGH 1 · MEDIUM 1)**

- HIGH: 송장 금액 USD 9,556.52 > 신용장 한도 9,250.00 → **UCP600 18(b)·30(b)**
- MEDIUM: B/L 서명자 자격 미표시 → **UCP600 20(a)(i)**

각 하자 카드에 **조항 번호 + 조항 원문 + 수정 제안**이 붙어 있는지 확인하세요.

### ③ 고위험 판정 — `screen3_live.html`
> **등급 D · 40점 · 하자 3건**

- HIGH: 송장 모델번호 `AH-702` ≠ 신용장 `AH-720` → **UCP600 18(c)**
- HIGH: 선적일 07-18 > 최종선적기일 07-15 (3일 초과) → **UCP600 14조·44C**
- MEDIUM: B/L 서명자 자격 미표시 → **UCP600 20(a)(i)**

> **말할 것:** "사람이 눈으로 놓치기 쉬운 한 글자 차이를 잡아내고, 왜 하자인지 조항으로 설명합니다."

**이 화면들을 직접 다시 만들어 보여줄 수 있습니다:**

```bash
python3 render/render_report.py benchmark/cases/DEFECT-004.json --out /tmp/live.html
```

아무 케이스나 넣어도 즉시 리포트가 나옵니다 — 하드코딩이 아니라는 증명입니다.

## 장면 4 — 환노출 시뮬레이터 (2분)

`screen4_fx_simulator.html`을 열면 환율 입력칸 옆에 **`● 실데이터 2026-07-xx 한국은행 ECOS`** 라벨이 붙어 있습니다. `demo.sh`가 조회한 그날 매매기준율이 자동으로 들어갑니다.

**변동폭 슬라이더**를 움직이면 3시나리오 손익과 헤지 처방 문구가 실시간 재계산됩니다.

> **말할 것:** "환율은 한국은행 ECOS API에서 실시간 조회한 값입니다. 조회에 실패하면 시연용 기본값으로 자동 대체되어 데모가 멈추지 않습니다."

라벨이 "시연용 기본값"으로 보이면 네트워크·키 문제입니다. `python3 pipeline/fx_rates.py --check`로 진단하세요.

이어서 정확도:

```bash

```

| 지표 | 값 | 의미 |
|---|---|---|
| 하자 검출 F1 | **1.000** (TP 22 · FP 0 · FN 0) | 규칙 구현에 모순 없음 |
| 정상 오탐률 | **0%** (20건 중 0건) | 함정 정상 4건 포함 |
| 등급 일치율 | **100%** | A~D 판정이 정답과 일치 |

```bash
python3 crosscheck_independent.py | tail -5
```

> **40건 전부 라벨 == 독립검출. 우발 하자 0건.**

생성기와 **규칙을 공유하지 않는 별도 구현**으로 정답 라벨을 재검증한 결과입니다.

### ⚠️ 이 수치를 말할 때의 원칙

F1 1.000은 **규칙 구현 검증**이지 실서비스 성능이 아닙니다. 실제 성능은 서류 이미지부터 시작하는 종단 평가 수치이고, 오늘 측정한 값은:

| 종단 지표 (GPT-4o, 6건) | 값 |
|---|---|
| 필드 추출 정확도 | **96.6%** |
| 문서 분류 정확도 | **100%** |

한정어 없이 "정확도 100%"라고 말하지 않습니다. `D1_회의_결정브리프.md` 안건 2 참조.

## 오늘 증명된 것 / 아직 아닌 것

**증명됨**

- 무역서류 3종을 JSON에서 자동 생성·렌더링 (120장 몇 초)
- UCP600 9개 유형 하자를 조항 인용과 함께 판정 (F1 1.000, 오탐 0%)
- GPT-4o로 서류 이미지에서 필드 추출 (정확도 96.6%, 분류 100%)
- 판정이 LLM 유무와 무관하게 결정적 — 재현 가능
- Claude/GPT 프로바이더 교체 가능
- 한국은행 ECOS 환율 API 실호출 성공

**아직 아님**

- 업로드 → 판독 화면이 실제 파이프라인과 연결되지 않음 (D6)
- 종단 하자 검출 정밀도 (오늘 수정 후 미재측정 — 내일 `--limit 6` 재실행)
- 환율 자동 조회가 화면에 반영되지 않음 (D5)
- UCP600 인용문이 공식 국문 번역과 미대조 (D4)
