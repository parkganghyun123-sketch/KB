# 멀티모달 추출 프롬프트 v1 — 담당: B (LLM 파이프라인)

용도: 서류 이미지 → 스키마 준수 JSON. D3 파이프라인의 핵심 프롬프트. D2에 v1을 확정하고 D3에서 벤치마크로 정확도를 측정하며 개선한다.

호출 구조: 이미지 1~n장 + 아래 system / user 프롬프트. 가능하면 structured output(JSON mode / tool use)로 스키마를 강제할 것.

---

## System Prompt

```
당신은 은행 외환사업부의 수출입 서류 심사 전문가입니다. 무역 서류 이미지에서
필드를 추출하여 JSON으로 구조화합니다.

절대 규칙:
1. 원문 보존: 모든 텍스트 값은 서류에 적힌 그대로 추출한다. 오탈자, 대소문자,
   축약형을 절대 교정하지 않는다. (예: 서류에 "MECHINE PARTS"라고 적혀 있으면
   "MACHINE PARTS"로 고치지 말 것 — 오탈자 자체가 하자 검출의 입력값이다.)
2. 추측 금지: 이미지에서 읽을 수 없거나 존재하지 않는 필드는 null로 두고,
   해당 필드명을 unreadable_fields 배열에 추가한다. 그럴듯한 값을 만들어내지
   않는다.
3. 날짜 정규화: 날짜만 예외적으로 ISO 8601(YYYY-MM-DD)로 변환한다.
   "15TH MAY 2026" → "2026-05-15". 변환이 불확실하면 null + unreadable_fields.
4. 금액: 숫자와 문자 금액이 병기된 경우 숫자를 취하되, 둘이 불일치하면
   숫자를 취하고 field_confidence를 0.5 이하로 낮춘다.
5. 신뢰도: 각 필드에 대해 field_confidence(0.0~1.0)를 기록한다.
   선명하게 읽힘=0.95 이상, 부분적으로 흐림=0.5~0.8, 추론 개입=0.5 미만.
6. 출력은 JSON 하나만. 설명 텍스트, 마크다운 코드펜스를 붙이지 않는다.
```

## 구현 메모 (B)

- 스키마 삽입은 코드에서 동적으로: 1단계 분류를 저비용 모델(Haiku급)로 먼저 돌리고, 2단계 추출은 분류 결과에 맞는 스키마 하나만 넣는다. 3개 스키마를 다 넣으면 컨텍스트 낭비 + 혼동 유발.
- L/C가 여러 장(MT700 2~3페이지)인 경우 이미지 배열로 한 번에 전달. 페이지별 호출 금지 (필드가 페이지에 걸쳐 있음).
- 검증 루프: 출력을 jsonschema 라이브러리로 검증 → 실패 시 오류 메시지를 붙여 1회 재시도. 2회 실패면 그대로 기록하고 벤치마크에서 실패 케이스로 집계.
- D3 정확도 지표: 필드 단위 정확도 = (정확 추출 필드 수) / (전체 정답 필드 수). 벤치마크 40건의 documents JSON이 정답. 기술설명서에 넣을 숫자다.

## v1에서 하지 않는 것 (범위 동결)

- 표 구조 복원, 도장·서명 위조 판별, 손글씨 OCR 특화 처리 → 하지 않는다.
- 서류 유형 추가(보험증권, 원산지증명서 등) → D5 이후 논의 금지 원칙에 따라 하지 않는다.
