### A-5R. 생성기 수정 내용 리뷰 — 새 요청 (30분)

제가 `benchmark/generate_cases.py`를 고쳤는데, 데이터 담당인 A가 검토해 주시면 좋겠습니다.

**① 포장 개수 (`base_case`)**
```python
pkg_count = qty if unit == "CTN" else max(1, qty // 25)
```
거래 단위가 이미 CTN이면 수량 자체가 포장 개수입니다. 기존 `qty // 25`는
L/C "500 CTN" ↔ B/L "20 CARTONS" 같은 모순을 만들었습니다.
→ **PCS·SET·MT 제품의 `// 25`(25개입 카톤) 가정이 업종별로 타당한지** 봐주세요.
특히 `POLYPROPYLENE RESIN COMPOUND`는 단위가 MT라 "MT ÷ 25 = 카톤 수"가 물리적으로 이상합니다.

**② 송장 산술 (`set_invoice_amount`)**
단가를 먼저 2자리로 확정하고 총액을 파생시켜 **수량 × 단가 = 총액**이 정확히 성립하게 했습니다.
기존에는 총액에서 단가를 역산·반올림해 최대 128 USD가 어긋났습니다.

**③ 교차검증기 강화 (`crosscheck_independent.py`)**
- 산술 허용오차 1% → 0.01 (구 허용치가 수십 USD 오차를 통과시킴)
- 포장수량·화인(C/NO. 1-N) 정합성 검사 추가

**검토 방법:**
```bash
cd ~/KB/TradeGuard/benchmark
```
