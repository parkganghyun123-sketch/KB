### §0-1. 공공데이터포털 API 신청 링크 (정확한 주소)

**포털**: https://www.data.go.kr — 회원가입 후 각 페이지에서 `활용신청` 버튼 클릭

| 우선순위 | 데이터셋 | 신청 URL | 용도 |
|---|---|---|---|
| **1순위 (필수)** | 관세청_관세환율정보(GW) | https://www.data.go.kr/data/15101230/openapi.do | 주간 관세환율 — 화면4 환노출 모듈 보조 |
| 2순위 | 관세청_품목별 국가별 수출입실적(GW) | https://www.data.go.kr/data/15100475/openapi.do | HS코드×국가 무역통계 — 거래 규모 맥락 |
| 참고 | 관세청_국가별 수출입실적(GW) | https://www.data.go.kr/data/15101612/openapi.do | 국가 단위 집계 |
| 참고 | 관세청_품목별 수출입실적(GW) | https://www.data.go.kr/data/15101609/openapi.do | 품목 단위 집계 |

**신청 절차**
1. data.go.kr 회원가입·로그인
2. 위 URL 접속 → 우측 상단 **활용신청**
3. 활용목적: `앱개발(교육)` 또는 `참고자료` 선택 · 목적 기재 (예: "2026 KB AI Challenge 출품작 개발 — 수출입 서류 검증 및 환노출 분석")
4. 라이선스 동의 → 신청
5. **마이페이지 → 오픈API → 개발계정**에서 인증키(서비스키) 확인

**주의 3가지**
- 개발계정은 **일 1,000건** 트래픽 제한 — 개발·데모에는 충분합니다.
- 자동승인 데이터셋은 즉시, 심의 대상은 1~2일 소요. **오늘 신청해야 안전합니다.**
- 발급키는 **URL 인코딩/디코딩 두 형태**로 제공됩니다. 요청 시 인코딩된 키를 쓰되, 라이브러리가 재인코딩하면 오류가 나므로 `requests`의 `params=`로 넘길 때는 **디코딩 키**를 쓰세요.

> ⚠️ **환율의 주 데이터원은 이미 확보된 한국은행 ECOS(731Y001)입니다.** 관세청 관세환율은
> 주간 고시환율이라 실시간성이 떨어지므로 **보조·검증용**입니다. 관세청 API 승인이 늦어도
> D5는 진행 가능하니, 이것 때문에 일정을 멈추지 마세요.

## 1. A(데이터)에게 요청

**이미 만들어져 있는 것** (중복 작업 금지)
- `benchmark/generate_cases.py` — 40건 생성기 (시드 고정, 재현 가능)
- `benchmark/evaluate.py` — 정밀도/재현율/F1/등급일치율/오탐률 산출
- `benchmark/cases/` — 생성된 40건 JSON (하자 20 · 정상 20, 함정 정상 4 포함)

**요청 사항**

| # | 요청 | 왜 필요한가 | 마감 |
|---|---|---|---|
| A-1 | **케이스 육안 검수** — 하자 5건 + 정상 5건을 직접 읽고 "이게 정말 하자/정상인가" 확인 | 생성 로직이 만든 하자가 실무적으로 말이 되는지는 사람만 판단 가능 | D2 저녁 |
| A-2 | **교차 검증** — 하자 20건을 별도 프롬프트(또는 다른 모델)로 재검사해 **우발 하자** 색출 | 의도한 하자 외 다른 하자가 섞이면 정답 라벨이 틀린 것이 됨 | D3 |
| A-3 | **PNG 렌더링 실행** — `generate_cases.py --render` 후 Playwright로 120장 생성 | B의 엔드투엔드 평가 입력물. **B가 이걸 기다림** | D2 오후 |
| A-4 | **ECOS 환율 연동 모듈** — 731Y001 조회 → `fx_exposure.schema.json`의 `spot_rate` 채우기 | 화면 4를 실데이터로 전환 | D5 |
| A-5 | 케이스 다양성 보강 (선택) — LLM 생성 케이스 5~10건을 섞어 규칙성 완화 | 현재 40건은 전부 코드 생성이라 패턴이 규칙적 | D4, 여유 시 |

**A가 판단해야 할 것**: 벤치마크를 40건에서 더 늘릴지. 늘리면 지표 신뢰도는 오르지만 검수 부담이 커집니다. **권고: 40건 고정, 대신 검수 품질에 시간 투자.**

## 2. B(LLM 파이프라인)에게 요청

**이미 만들어져 있는 것**
- `pipeline/extract.py` — 2단계(분류→추출) + 스키마 검증 재시도. **단 실제 API 키로 미검증**
- `pipeline/detect.py` — 하이브리드 하자 검출 (결정적 규칙은 코드, 의미 비교는 LLM + 오프라인 폴백)
- `pipeline/ucp600_kb.json` — 조항 인용 KB (13개 조항)

**요청 사항**

| # | 요청 | 왜 필요한가 | 마감 |
|---|---|---|---|
| B-1 | **extract.py 실 API 스모크 테스트** — A가 렌더링한 PNG 5~10건으로 실행 | 지금까지 추출 파이프라인은 **한 번도 실제로 돌아본 적이 없음**. 최대 리스크 | D3 오전 |
| B-2 | **엔드투엔드 평가 스크립트** — `PNG → extract → detect → 정답 대조` 전 구간 | 현재 F1 1.000은 정답 JSON을 그대로 넣은 수치. **진짜 성능은 여기서 나옴** | D3~D4 |
| B-3 | **필드 단위 추출 정확도 측정** — (정확 추출 필드 수)/(전체 필드 수) | 기술설명서의 핵심 지표 2개 중 하나 | D3 |
| B-4 | **LLM 모드 재평가** — `ANTHROPIC_API_KEY` 설정 후 `evaluate.py` 재실행 | 의미 비교가 휴리스틱보다 나은지 확인. 안 나으면 휴리스틱 유지가 합리적 | D4 |
| B-5 | **UCP600 인용문 원문 대조** — `ucp600_kb.json`의 13개 조항 요지를 공식 국문 번역과 대조 | ⚠️ 현재는 요약본. **틀린 조항 인용은 심사에서 치명타** | D4 |
| B-6 | 하자 심각도(severity) 기준 팀 합의 — 현재 high/medium 배분이 임의적 | 등급 산식의 근거를 질문받으면 답해야 함 | D4 |

**B가 판단해야 할 것**: 추출 모델을 Sonnet으로 갈지 Haiku로 갈지. 정확도와 비용/속도 트레이드오프인데, 데모는 5초 안에 끝나야 합니다.

## 4. 팀 전체가 함께 결정해야 할 것 (D1 밤 회의 안건)

1. **스키마 동결 확인** — `schemas/` 6종을 변경하려면 3인 합의. 오늘 이후 변경은 통합 지옥의 시작입니다.
2. **정확도 지표를 어떻게 발표할 것인가** — 현재 벤치마크 F1 1.000은 생성기와 검출기가 같은 규칙을 공유해서 나온 값입니다. `benchmark/README.md`에 정직한 표현 문구를 써뒀으니 **팀 전체가 같은 말을 하도록** 합의하세요. 한 명이라도 "저희 정확도 100%입니다"라고 하면 반박당합니다.
3. **L/C 감소 추세 반박 대응** — "요즘 L/C 잘 안 쓰지 않나요?" 질문에 대한 통일된 답변. (권고: "그래서 저희는 L/C만이 아니라 T/T 거래의 서류 정합성과 외화 익스포저까지 포괄합니다. L/C 검증은 3개 모듈 중 하나입니다.")
4. **기능 동결일** — D5 이후 신규 기능 추가 금지. 예외 없이.
