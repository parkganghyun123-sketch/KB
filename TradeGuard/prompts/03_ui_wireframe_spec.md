# UI 와이어프레임 스펙 — 담당: C (UI + 문서)

용도: D2에 와이어프레임을 확정하고, D6 통합 때 이 스펙 그대로 구현한다. 화면은 4개를 넘기지 않는다. "한 컷으로 설명되는 데모"가 목표: **서류를 올리면 하자가 빨갛게 뜬다.**

기술: Next.js 단일 페이지(라우팅 없이 상태 전환) 또는 Streamlit. D5까지 Next.js 진행이 밀리면 즉시 Streamlit으로 전환한다(전환 판단은 D5 저녁, C가 결정).

---

## 화면 1 — 업로드

- 드롭존 3칸: L/C / Commercial Invoice / B/L (각각 이미지·PDF)
- 데모 버튼: "샘플 케이스 불러오기" (심사 시연용 — 파일 준비 없이 클릭 1번으로 진행)
- 업로드 즉시 문서 분류 결과 뱃지 표시 (extraction 1단계 출력)

## 화면 2 — 판독 결과 (extraction JSON 렌더)

- 좌: 원본 이미지 / 우: 추출 필드 테이블
- field_confidence < 0.8 필드는 노란 배경 + "확인 필요" 뱃지
- unreadable_fields는 회색 "판독 불가" 표시
- 하단 CTA: "하자 검사 실행"

## 화면 3 — 하자 리포트 (discrepancy_report 렌더) ★ 데모의 클라이맥스

- 상단: overall_risk.grade를 대형 등급 카드로 (A 초록 ~ D 빨강) + score + summary_ko
- 하자 카드 리스트 (severity 내림차순):
  - description_ko (제목)
  - evidence: 문서명·필드·값을 나란히 배치, 불일치 값은 **빨간 하이라이트**
  - ucp_basis: "UCP600 18(c)" 뱃지 + quote_ko 인용 블록
  - suggested_fix_ko: 연한 파랑 박스 "수정 제안"
- 원본 이미지 위 해당 영역 하이라이트는 **하지 않는다** (좌표 매핑은 8일 범위 밖. 필드값 하이라이트로 충분)

## 화면 4 — 환노출 & 처방 (fx_exposure 렌더)

- 상단: 현금흐름 캘린더 (타임라인 바, inflow 초록/outflow 빨강)
- 중단: 3시나리오 손익 막대 차트 (base / 원화강세 / 원화약세, pnl_krw)
- 하단: KB 상품 매칭 카드 2~3장 (product_name_ko, fit_reason_ko) + "이 위험을 없애려면" 헤드라인

## D2 작업 지시 (C)

1. 오전: 위 4화면을 Figma 또는 손그림 → 팀 합의 (30분 리뷰, A·B 참여)
2. 오전: **합성 서류용 HTML 템플릿 3종 제작** (A의 렌더링 파이프라인 입력물 — 최우선)
   - L/C: SWIFT MT700 텔렉스 스타일 (고정폭 폰트, :20:, :31D: 태그 형식)
   - Invoice: 일반 상업송장 레이아웃 (레터헤드, 품목 테이블, 서명란)
   - B/L: 표준 B/L 양식 (상단 로고, 필드 그리드, 하단 서명 블록)
   - 각 템플릿은 benchmark_case.documents의 JSON을 Jinja2/JSX로 주입받는 구조
3. 오후: 화면 3(하자 리포트)부터 정적 목업 구현 — 데모 가치의 80%가 이 화면이다.
