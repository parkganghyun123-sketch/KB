## 구성

| 구분 | 건수 | 내용 |
|---|---|---|
| 하자 케이스 | 20 | 9개 유형 + 복합 하자 2건 (총 하자 인스턴스 22개) |
| 정상 케이스 | 16 | 완전 정합 |
| **함정 정상** | 4 | 하자처럼 보이나 UCP600상 정상 — **오탐 측정 전용** |

함정 정상 4종:
1. 금액이 L/C보다 7% 크지만 39A 과부족 허용 10% 이내 (30(b))
2. B/L 명세가 일반 표현 — 14(e)상 저촉 아님
3. 분할선적 허용 조건 + 실제 단일 선적
4. 선적일 = 최종선적기일 당일 (경계값)

## ⚠️ 이 수치를 그대로 발표하면 안 되는 이유 (반드시 읽을 것)

**생성기와 검출기가 같은 규칙 가정을 공유한다.** 하자를 주입한 코드와 하자를 찾는 코드가 동일한
UCP600 해석을 쓰기 때문에 100%가 나오는 것은 당연하다. 이건 "엔진이 완벽하다"가 아니라
**"규칙 구현에 내부 모순이 없다"는 회귀 테스트 통과**를 뜻한다.

기술설명서에는 이렇게 쓸 것 (**D1 회의 확정 문구 — 토씨 그대로 사용**):

> 합성 벤치마크 40건(하자 20 · 정상 20, 함정 정상 4건 포함)에 대한 규칙 정합성 검증에서
> 하자 검출 F1 1.000, 정상 케이스 오탐률 0%를 기록했다. 다만 본 벤치마크는 케이스 생성 규칙과
> 검출 규칙이 동일한 UCP600 해석을 공유하므로 **상한 성능(upper bound)** 을 나타내며,
> 실제 서류 이미지를 입력으로 하는 종단 성능은 별도로 측정한다.

**발표·Q&A 대사와 팀 합의 사항은 `D1_회의_결정브리프.md` 안건 2를 따를 것.**
누구도 "100%"를 한정어 없이 단독으로 말하지 않는다.

**한계를 먼저 밝히는 팀이 신뢰를 얻는다.** 숨기고 100%만 말하면 심사위원 질문 한 번에 무너진다.
