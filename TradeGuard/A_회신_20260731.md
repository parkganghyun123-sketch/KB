## A-9. 서류 자기모순 — 반영 완료

**판단:** `clean`(무사고)과 `on board`(본선적재)는 말씀하신 대로 별개 개념이다. 데이터 쪽(`clean: True`)은
바꿀 필요가 없다 — 진짜 문제는 **템플릿이 둘을 하나의 조건으로 묶어 인쇄한 것**이었다.
`bill_of_lading.html.j2` 하단 Freight 박스는 이미 `shipped_on_board.indicated`로 "Shipped on Board" vs
"Received for shipment"을 정확히 분기하고 있었는데, 상단 goods 영역의 `CLEAN ON BOARD` 문구만
`clean` 하나로 조건이 걸려 있어 같은 서류 안에서 서로 다른 말을 하고 있었다.

**수정** (`templates/bill_of_lading.html.j2` 82행):
```jinja
{% if bl.clean and bl.shipped_on_board.indicated %}<br><br>CLEAN ON BOARD
{% elif bl.clean %}<br><br>CLEAN
{% endif %}
```
본선적재가 인쇄될 때만 "CLEAN ON BOARD", 아닐 때는 "CLEAN"만 인쇄 — 화물 상태(무사고)는 여전히
주장하되 있지도 않은 본선적재를 주장하지 않는다. `"CLEAN RECEIVED FOR SHIPMENT"`는 쓰지 않았다:
이 B/L 서식 자체가 "Received for shipment" 박스를 이미 별도로 갖고 있어 그쪽에서 상태를 표시하고,
goods 영역은 화물 상태만 담당하는 편이 서식 두 군데가 같은 말을 반복하지 않아 더 낫다고 판단했다.

**다른 하자 유형 훑어본 결과:** 같은 유형(주입은 됐는데 다른 필드가 안 따라가는 모순)은
`BL_SIGNATURE_DEFECT`(서명은 있고 자격만 비움 — 모순 아님), `LATE_SHIPMENT`/`LC_EXPIRED_...`(이미
제시일까지 함께 밀어주는 주석 처리가 돼 있음 — DEFECT-011 회귀로 이미 막혀 있었음), `PORT_MISMATCH`
(다른 연동 필드 없음) 전부 확인했고 **추가 발견 없음.**

회귀 테스트 추가: `test_all.sh` — "clean B/L도 본선적재 미표기 시 'CLEAN ON BOARD' 인쇄 안 함 (A-9)".

첫 번호 1회) 유지해 시드 스트림을 건드리지 않았다 — 다만 일련번호가 7자리→6자리로 줄어 컨테이너
번호 자체(문자열 값)는 전부 바뀐다(체크디짓 자리 추가 때문에 불가피).

## A-6. 컨테이너 적재 가정 — 검토 완료, 밀도 보정 반영

1. **67 CBM / 26,000kg (40ft HC):** 타당하다고 판단. 40ft HC 실제 내용적은 약 76 CBM이지만 팔레트·결속
   손실을 빼면 통상 58~68 CBM을 유효 적재량으로 잡고, 페이로드도 게이트웨이별 max gross(약
   28,180kg) - tare(약 3,900kg) 기준 26,000~28,000kg대가 통상치다. **변경 없음.**
2. **포장당 0.045 CBM 일괄 적용:** 말씀대로 문제였다. 티셔츠 카톤(가볍고 부피가 큼)과 스테인리스
   피팅(무겁고 조밀함)을 같은 부피로 잡으면 총중량 대비 총용적 비율이 비현실적이다. `WEIGHT_KG_PER_UNIT`와
   같은 패턴으로 `CBM_PER_PACKAGE`(업종코드→포장당 CBM) 테이블을 추가해 품목별로 다르게 반영했다.
   **주의:** 이 수치들은 화물운송 통상치를 근거로 한 추정값이며 감사된 실측 데이터는 아니다 — 더
   정확한 수치가 있다면 언제든 교체 가능하도록 `WEIGHT_KG_PER_UNIT` 옆에 나란히 뒀다.
3. **rng 시드 스트림:** `containers()`는 A-7에서 이미 확인(순서·횟수 불변). `CBM_PER_PACKAGE` 적용은
   rng를 전혀 소비하지 않는 순수 계산이라 스트림에 영향 없음. 생성기 재현성 테스트(시드 고정) 통과 확인.

## A-8. REMEDY_MAP 실무 타당성 — 검토 완료

| 하자 유형 | 판단 | 근거 |
|---|---|---|
| `AMOUNT_EXCEEDS_LC` | **유지 + 안내 보강** | 서류 도구가 할 수 있는 건 "제시 서류를 L/C 한도 이내로 압축"뿐이다. 초과분 T/T 분리는 결제 방식 결정이지 필드 수정이 아니다 — 값 자체는 그대로 두고 `actor_ko`에 "초과분은 별도 T/T 정산 가능"을 덧붙였다. |
| `GOODS_DESC_MISMATCH` | **유지** | UCP600 14(e)는 상업송장의 상품명세가 신용장과 **상응(correspond)** 할 것을 요구한다(다른 서류의 "저촉 없는 일반표현" 허용과 다른 기준). 45A 원문 그대로 옮기는 게 가장 안전한 치유가 맞다. |
| `BL_SIGNATURE_DEFECT` | **유지** | 실무상 원양 B/L은 운송인 본인이 아니라 현지 대리인(agent)이 서명하는 경우가 훨씬 흔하다. `agent_for_carrier` 기본값이 `carrier` 직접 서명보다 현실적이다. |
| `PORT_MISMATCH` | **유지** | 이 벤치마크의 주입 방식은 "실제 선적항은 그대로인데 B/L 표기만 오기"를 가정한다(다른 항구로 실제 선적이 바뀐 게 아님) — 이 전제라면 운송사의 B/L 정정이 맞는 조치다. 실제 선적항 자체가 바뀐 경우라면 조건변경이 맞겠지만, 그건 이 하자 유형이 표현하는 시나리오가 아니다. |
| `LATE_SHIPMENT` / `LC_EXPIRED_...` | **유지** | 이미 일어난 사실(선적일·제시기한 경과)은 서류를 다시 써도 되돌릴 수 없다 — waiver/amendment가 맞다. 발표의 "고칠 수 없는 걸 고쳤다고 말하지 않는다" 장면과 정확히 부합한다. |

**결론:** REMEDY_MAP 5개 항목 모두 실무 판단상 문제 없음. `AMOUNT_EXCEEDS_LC` 안내 문구만 보강.
