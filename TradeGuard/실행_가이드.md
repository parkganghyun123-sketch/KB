## 1. 터미널에서 직접 실행하기 (API 키 불필요 · 비용 0원 · 3분)

```bash

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python3 -m uvicorn server.app:app --port 8000
```

화면 첫머리의 **「샘플 서류로 먼저 둘러보기」**를 누르면 케이스 3건이 나옵니다.

| 케이스 | 결과 | 확인 포인트 |
|---|---|---|
| **CLEAN-017** | A등급 | 송장 금액이 신용장 한도를 6.9% 초과하는데도 정상 판정 — 신용장 39A 과부족 허용 조건을 반영합니다 |

| **DEMO-001** | D등급 | 치유 불가 하자 포함 — 수정해도 제출 가능 상태가 되지 않습니다 |

## 3. 정확도 수치 직접 재현 (API 키 불필요)

논문식 주장이 아니라 **직접 돌려 확인하실 수 있습니다.**
LLM 판독 결과 40건을 `benchmark/cases/extracted/`에 포함해 두었습니다.

```bash
cd TradeGuard
python3 - <<'PY'
import sys, json, glob; sys.path.insert(0, 'pipeline')
from detect import build_report, d as pd
tp = fp = fn = g = 0
for f in sorted(glob.glob('benchmark/cases/*.json')):
    c = json.load(open(f))
    ex = json.load(open(f"benchmark/cases/extracted/{c['case_id']}.json"))
    r = build_report(c['case_id'], ex['documents'], pd(ex.get('presentation_date')))
    got = {x['type'] for x in r['discrepancies']}
    exp = {x['type'] for x in c['ground_truth']['discrepancies']}
    tp += len(got & exp); fp += len(got - exp); fn += len(exp - got)
    g += r['overall_risk']['grade'] == c['ground_truth']['overall_risk']['grade']
p, rc = tp/(tp+fp), tp/(tp+fn)
print(f"정밀도 {p:.3f} · 재현율 {rc:.3f} · F1 {2*p*rc/(p+rc):.3f} · 등급 일치 {g}/40")
PY
```

출력: `정밀도 0.870 · 재현율 0.909 · F1 0.889 · 등급 일치 35/40`

> 이 값은 **서류 이미지부터 시작하는 종단 성능**입니다.
> 규칙 정합성 F1 1.000과는 다른 지표이며, 실제 성능은 이쪽으로 보셔야 합니다.
> 측정 시점은 2026-07-31 오전 렌더본 기준입니다.

## 4. 실제 AI 판독까지 확인하려면 (API 키 필요 · 유료)

서류 이미지에서 필드를 읽어내는 단계까지 보시려면 키가 필요합니다.
**서류 3장에 약 $0.06**이 발생합니다.

```bash
cd TradeGuard
cp .env.example .env
```

`.env`를 열어 `OPENAI_API_KEY` 또는 `ANTHROPIC_API_KEY` 중 하나를 넣고 서버를 다시 실행합니다.
첫 화면에서 아래 이미지를 끌어다 놓으십시오.

```
benchmark/cases/rendered/DEFECT-019_lc.png
benchmark/cases/rendered/DEFECT-019_invoice.png
benchmark/cases/rendered/DEFECT-019_bl.png
```

**「서류 제시(예정)일」 칸에 `2026-07-21`을 입력해 주십시오.**

제시일은 서류에 인쇄되지 않는 값이라 추출로는 알 수 없고, 담당자가 은행에 내는 날을
정하는 값이라 입력칸을 두었습니다. 비워 두면 오늘 날짜로 계산하는데, 이 시연용 서류는
과거 날짜로 발행돼 있어 UCP600 14(c) 제시기한 경과가 일괄로 잡힙니다.

CLEAN-017을 올리실 경우 제시일은 `2026-06-30`입니다.

## 5. 실행이 안 될 때

| 증상 | 원인과 조치 |
|---|---|
| `ModuleNotFoundError` | `pip install -r requirements.txt`를 실행했는지 확인해 주십시오 |
| 포트 8000 사용 중 | `--port 8001` 등으로 바꿔 실행하시면 됩니다 |
| 업로드 버튼이 비활성 | LLM 키가 없는 상태입니다. 샘플 모드로 확인하실 수 있습니다 |
| 환율이 `fallback`으로 표시 | 한국은행 ECOS 조회 실패입니다. 판정에는 영향이 없고 환노출 계산에만 고정값을 씁니다 |
| 서류 이미지가 없음 | 저장소 용량 때문에 6장만 포함했습니다. 나머지는 `python3 render/render.py benchmark/cases/*.json --out benchmark/cases/rendered --png`로 생성됩니다 (Playwright 필요) |

## 6. 구조를 보실 때

| 파일 | 내용 |
|---|---|
| `pipeline/detect.py` | **하자 판정 — 결정적 규칙.** AI를 호출하지 않습니다 |
| `pipeline/remedy.py` | 수정값 도출. 신용장 기재값에서 계산합니다 |
| `pipeline/extract.py` | 서류 판독. **여기서만 AI를 씁니다** (서류 1장당 종류 판별 1회 + 필드 추출 1회) |
| `pipeline/ucp600_kb.json` | UCP600 조항 지식베이스 |
| `server/app.py` | 백엔드 API |
| `server/app.html` | 웹 앱 (빌드 도구 없이 단일 파일) |
| `schemas/` | 팀 간 데이터 계약 6종 |
| `benchmark/` | 합성 케이스 40건 + 정답 라벨 + 평가·교차검증 스크립트 |

**설계 원칙은 「AI는 읽기만, 판정은 코드가」입니다.** 개발 중 하자 판정을 AI에 맡겼을 때
정상 케이스 6건을 모두 오탐하고 실제 하자 2건을 놓치는 것을 실측했고, 그 결과 판독만
AI에 남겼습니다. 자세한 내용은 `README.md`에 있습니다.

## 7. 한계

- 벤치마크 40건은 **전량 합성 데이터**입니다. 실서류는 기업 기밀이라 확보하지 못했고,
  공개 서식을 기준으로 만들었습니다.
- 사용자 인증·권한 기능이 없습니다. 로컬 사전점검 프로토타입 범위입니다.
- 이 도구는 은행의 최종 심사가 아니라 **제출 전 참고용 사전 점검**입니다.
- 서류 판독 단계에서 이미지가 외부 생성형 AI 서비스로 전송됩니다. 실제 도입 시에는
  온프레미스 판독 모델로 교체하는 것을 전제로 설계했습니다.
