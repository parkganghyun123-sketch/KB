## 1. 프로젝트가 뭔지

**TradeGuard** — 제8회 KB AI Challenge 출품작.
수출 서류(신용장 L/C·상업송장·B/L) 이미지를 올리면 은행이 지급을 거절할 **하자(discrepancy)**를
UCP600 조항 인용과 함께 찾아주고, 최근엔 **수정 제안 → 승인 → 재심사**까지 자동으로 닫는 에이전트.

핵심 설계 원칙: **"LLM은 읽기만, 판정은 코드가"**
- LLM(GPT-4o/Claude)이 이미지에서 필드를 구조화 JSON으로 추출
- 하자 판정·수정 제안은 100% 결정적 규칙(UCP600 기반)으로 처리 → 재현 가능, 평가비용 0원
- 근거: 상품명세 비교를 LLM에 맡기면 정상 케이스 6/6 오탐, 회사명 비교는 실제 하자 2건 미검출 → 규칙 기반으로 전환해 해결

위치: `~/KB/TradeGuard` (레포 루트는 `~/KB`, README는 루트에 있음)

## 3. 지금까지 진행 흐름 (커밋 60개, 요약)

### 초기 구축 (D1~D2)
- 화면1(업로드)·화면2(판독)·화면3(하자리포트)·화면4(환노출 시뮬레이터) 목업 → 실동작 SPA로 전환
- FastAPI 백엔드 연결: 업로드 → 추출 → 검출 → 환노출 전 과정
- 합성 서류 생성기(`generate_cases.py`) + 렌더러(Jinja2 → HTML/PNG, Playwright)
- 서식을 실제 표준(MT700, UCP600)과 대조해 필드 보완 (예: `:40E:` 누락 발견·추가)

### 포지셔닝 확정 (7/27~28)
- 공개 참가신청 16건 경쟁작 분석 → 수출입 영역 경쟁 2팀 확인
- **서류 하자 검출을 메인으로, 환노출 분석은 "대금 수취 시점 손익" 부가 분석으로 강등**
- KB 공식 채널 리서치 기반 B2B 금융 디자인시스템 적용 (자체 워드마크, 출품작 고지·면책, WCAG AA 대비, 반응형 3단계)

### 벤치마크 현실성 보정 (반복적으로 발견·수정)
사람이 렌더링된 서류를 육안으로 보다가 우발적 결함을 계속 발견하는 패턴:
- 상업송장·B/L 필드 채우기(A-2)
- B/L 포장수량 모순, 송장 산술 불일치 (C 발견)
- MT(무게 단위) 포장수량 물리적 불가능값 → 총중량 기준 25kg 백 수로 역산 (A 발견·수정, C가 타당성 검토)
- 컨테이너 적재 가능성 결함 (19/40건, B/L 용적·중량 대비 컨테이너 1개뿐이던 문제) → 40ft HC 기준 필요 대수 산출 (C 수정, A가 리뷰 예정)
- 환노출 산식이 지연 일수를 반영 못하던 결함 → √t 규칙 도입

### 종단 평가 1차 실행 (B, 커밋 `507b776`)
- 필드추출 95.5%, 문서분류 100%, 하자검출 F1 0.889, 등급일치 90.0%
- **주의: 이 수치는 그 이후 케이스가 4번 더 바뀌어서 stale 상태** (아래 "다음 할 일" 참고)

### 폐쇄 루프 구현 (C, 커밋 `d90d7b5`) — 최근 가장 중요한 기능
- 기존: 하자 발견 → 문장으로 "이렇게 고치세요" 안내하고 끝
- 지금: **L/C 기재값에서 결정적으로 도출한 수정값 제시 → 사용자 승인 → 재심사 → 등급 C→A "제출 가능"**
  - ⚠️ **정정(7/31)**: 초안에 "D→A"로 적었으나 **실측상 D→A 전이는 0건**이다.
    실제 전이는 C→A 11 · B→A 5 · C→C 4. D등급 케이스에는 치유 불가 하자가 섞여 있어
    설계상 A에 도달하지 않는다. 완결 시나리오 케이스는 `DEFECT-019`.
- 설계 핵심 2가지:
  1. 제안값을 LLM이 만들지 않음 — `pipeline/remedy.py`가 L/C 원문에서 결정적 도출 (하자의 정의가 "신용장과 다르다"이므로 정답은 이미 L/C에 있음)
  2. **치유 불가 하자 구분** — 선적기일 경과·제시기한 경과는 이미 벌어진 사실이라 서류를 다시 써도 안 고쳐짐 → 자동으로 "해결됨" 처리 안 하고 waiver/amendment 필요라고 남김
- 실측(`benchmark/closedloop_report.md`, 정답 JSON 기준):
  - 재심사 통과율(치유 가능 하자만 있는 16건): 100.0%
  - 치유 가능 하자 해소율: 100.0%
  - 제안값 정확도(L/C 기준값 일치): 100.0%
  - 수정으로 인한 신규 하자: 0건
  - 재심사 처리시간 평균 0.1ms
- **단, 이 100%는 "정답 JSON 위에서" 돌린 것.** 실제로는 LLM 추출값(필드정확도 95.5%) 위에 얹히므로, 추출 오류가 잘못된 수정 제안으로 안 이어지는지 아직 검증 안 됨 → B-2R 작업으로 보완 예정

`test_all.sh` 35항목 전량 통과 상태.
