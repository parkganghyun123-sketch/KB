# 2. 프로젝트 개요

**목적** — 수출기업이 은행에 신용장 서류를 제시하기 **전에** 스스로 하자를 찾아 고칠 수 있게 한다. 하자로 인한 지급거절·대금 회수 지연을 앞단에서 줄인다.

**주요 기능**

| # | 기능 | 진입점 |
|---|---|---|
| 1 | 서류 이미지 → 구조화 JSON 추출 (2단계: 분류 → 스키마 주입 추출) | `pipeline/extract.py` |
| 2 | UCP600 규칙 기반 하자 검출 + 조항 인용 | `pipeline/detect.py` |
| 3 | 위험 등급 A~D + 100점 스코어 | `detect.grade()` |
| 4 | 수정 제안 → 승인 → 재심사 → Before/After (**폐쇄 루프**) | `pipeline/remedy.py` + `POST /api/redetect` |
| 5 | 하자 → 지연 → 환노출 인과 분석 (√t 규칙) | `server/app.py: delay_block/fx_block` |
| 6 | 합성 벤치마크 40건 생성 + 서류 렌더링 | `benchmark/generate_cases.py`, `render/render.py` |
| 7 | 실동작 SPA (업로드/샘플 이중 모드) | `server/app.html` (834줄, 단일 파일) |

**사용자** — 1차: 수출 초보 중소기업 무역 담당자. 2차: 은행 매입심사 앞단 행원(B2B2C 모델, `우승전략_20260728.md` B-2절에서 확정).

**기술 스택** — Python 3.10+ / FastAPI 0.110+ / Jinja2 / Playwright / jsonschema / OpenAI·Anthropic SDK / 바닐라 JS SPA(빌드 도구 없음). 외부 API: 한국은행 ECOS(731Y001, 주), 관세청 관세환율·수출입실적(보조).

## 핵심 모듈 책임과 호출 관계

- **`detect.py`** — 순수 함수형. 외부 상태·네트워크 의존 없음(`date.today()` 제외 → §10 High-2 참조). `run_checks()`가 9개 규칙을 순차 적용, `disc()`가 `ucp600_kb.json`에서 조항을 부착. `_llm_client()`는 `TG_EXPLAIN_LLM=1`일 때만 호출되고 **판정을 뒤집지 않도록** 설명 생성에만 쓰입니다(`judge_goods_desc` 137~153행 주석 명시). 설계 의도가 코드로 강제돼 있습니다.
- **`remedy.py`** — `REMEDY_MAP` 딕셔너리 하나로 8개 치유 가능 유형 + 2개 치유 불가 유형을 선언적으로 관리. `apply_edits()`가 `deepcopy`로 원본 불변을 보장. 금액 수정 시 단가를 `math.floor`로 내림해 한도 재초과를 방지(175행) — 커밋 `da18002`에서 반올림 오차 결함을 잡은 흔적이 남아 있습니다.
- **`server/app.py`** — 도메인 로직을 갖지 않고 조립만 합니다. `analyze()` 하나가 report/delay/remedies/fx/audit을 합성. 얇은 층 유지가 잘 됐습니다.
- **`app.html`** — 단일 파일 SPA. `esc()` 헬퍼로 사용자 표시 문자열을 일관되게 이스케이프. 환노출 산식(`TRADING_DAYS=252`, `Z95=1.645`, √t)이 백엔드와 동일 상수로 중복 구현돼 있고, **그 동일성을 테스트가 강제**합니다(`test_all.sh` "환노출 산식이 3개 구현체에서 동일"). 중복을 인지하고 회귀로 막은 것 — 적절한 트레이드오프입니다.

- **충족 근거**: 샘플 모드(무료·오프라인)가 실제로 동작 — 은행 내부망 제약 대응 감각. B2B2C 모델이 `우승전략` B-2에서 확정됨. `llm.py`의 프로바이더 추상화는 온프레미스 LLM 대체 가능성의 **코드 근거**로 쓸 수 있습니다.
- **부족한 점**: **As-Is / To-Be 업무 흐름도가 어느 문서에도 없습니다.** "누가, 업무 어느 지점에서, 어떤 절차로 쓰는가"가 산출물로 존재하지 않음.
