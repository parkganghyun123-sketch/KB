# 벤치마크 검수 리포트 (A-1 육안검수 · A-2 교차검증)

- 담당: A(데이터) · 작성 2026-07-26
- 대상: `benchmark/cases/` 40건 (하자 20 · 정상 20, 함정 정상 4 포함)
- 도구: `benchmark/crosscheck_independent.py` (생성기와 규칙 비공유 별도 구현)

## 결론 먼저

**정답 라벨은 유효하다.** 독립 교차검증에서 40건 전부 라벨과 독립검출이 일치했고,
의도한 하자 외 **우발 하자(제2 하자)는 0건**이다. 라벨 기반 정확도 지표는 그대로 발표해도 된다.

다만 **케이스 현실성(realism)·스펙 준수**에서 보정 권고 4건을 발견했다. 이들은 하자 검출 라벨의
정오와는 무관하지만, 렌더링된 서류를 심사위원이 눈으로 볼 때 신뢰도를 떨어뜨릴 수 있어
D3~D4 중 `generate_cases.py`를 소폭 수정할 것을 권고한다.

## A-1. 육안 검수 (하자 5 · 정상 5)

각 케이스의 3개 서류를 직접 읽고 "라벨이 실무적으로 타당한가"를 판정했다.

| 케이스 | 라벨 | 육안 판정 | 메모 |
|---|---|---|---|
| DEFECT-001 | AMOUNT_EXCEEDS_LC (easy) | ✅ 타당 | INV 13,309.29 > L/C 12,800(tol 없음). 명백한 초과. |
| DEFECT-005 | GOODS_DESC_MISMATCH (hard) | ✅ 타당 | 모델번호 BC-990→BC-997. 1자 차이의 미세 불일치로 hard 난이도 적절. |
| DEFECT-008 | BENEFICIARY_NAME_MISMATCH (hard) | ✅ 타당 | "KOWON ENERGY CELL **COMPANY LTD**" vs 수익자 "…CO., LTD." — 표기 불일치. 실무 하자 맞음. |
| DEFECT-011 | LC_EXPIRED_OR_LATE_PRESENTATION | ⚠️ 라벨은 타당, 케이스에 결함 | 제시일(06-15)>선적일+21일(06-06) 및 유효기일(06-10) 경과 → 지연제시 성립. **단 L/C 내부 날짜 비정합(아래 이슈 3) 존재.** |
| DEFECT-019 | AMOUNT_EXCEEDS_LC + BL_SIGNATURE_DEFECT (복합) | ✅ 타당 | 금액 초과 + 서명자 자격(capacity) 누락. 두 하자 모두 독립 성립. |
| CLEAN-007 | 정상 | ✅ 정상, 단 규모 이상 | 완전 정합. 다만 거래액 **USD 5,800,000** (스펙 이탈, 이슈 1). |
| CLEAN-017 | 정상 (함정: tolerance) | ✅ 함정 유효 | INV 13,696 = L/C 12,800 ×**+7%**, 허용치 +10% 내 → 정상. 오탐 유발 설계 성공. |
| CLEAN-018 | 정상 (함정: B/L 일반표현) | ✅ 함정 유효 | B/L 명세 "GENERAL MERCHANDISE AS PER INVOICE" — 14(e) 허용. |
| CLEAN-019 | 정상 (함정: 분할선적) | ✅ 함정 유효 | 분할선적 ALLOWED + 단일 선적 → 위반 아님. |
| CLEAN-020 | 정상 (함정: 경계일) | ✅ 함정 유효 | 선적일 = 최종선적기일(07-09) 동일. "not later than"이므로 정상. |

**A-1 소견:** 하자/정상 판정은 10건 모두 실무적으로 타당. 함정 정상 4종은 의도대로 "하자처럼
보이나 규칙상 정상"이 성립하여 오탐 측정용으로 잘 설계됨. 결함은 라벨이 아니라 케이스 구성값
(거래규모·날짜 정합)에서 나온다 → 아래 이슈.

## A-2. 교차검증 (하자 20건 우발 하자 색출)

**방법:** 생성기와 규칙을 공유하지 않는 독립 검출기(`crosscheck_independent.py`)로 40건 전체를
재검사. tolerance 반영 금액검사, 상품명세 correspond(부분집합) 규칙, 명칭 정규화, 날짜/항구/서명/
본선적재 등 10개 유형을 독립 판정하여 각 케이스 `ground_truth`와 diff.

**결과:**

- 유형 라벨 교차검증: **40/40 일치. EXTRA(우발 하자) 0건, MISSING(미검출) 0건.**
- 즉, 의도한 하자 외에 코드가 실수로 심어놓은 제2의 하자는 발견되지 않음. 정답 라벨 신뢰 가능.

> 참고: 초기 독립검출기는 상품명세를 "완전일치"로 봐 정상 케이스를 전부 오탐했다. UCP600 18(c)의
> "correspond(상응)"는 송장이 L/C 명세의 축약형이어도 허용됨을 반영해 "송장 토큰 ⊆ L/C 토큰"
> 규칙으로 교정한 뒤에야 라벨과 일치했다. 이 과정 자체가 **"correspond ≠ 완전일치"** 라는
> 검출 규칙의 함정을 드러낸 것으로, B의 검출 프롬프트 작성 시 주의점으로 공유할 가치가 있다.

**부가 정합성 스캔(라벨 밖 이상치):** 아래 이슈 1·3·4로 정리.

## 발견 이슈 (우선순위)

### 이슈 1 — 거래 규모가 스펙(USD 30k~300k)을 이탈: 24/40건
`prompts/02`는 "USD 30,000~300,000"을 명시하나 실제 분포는 min 3,200 ~ max 5,800,000.
특히 **백만 달러대 4건**(CLEAN-007 5.8M, DEFECT-004/012/020 4.35M, DEFECT-015 2.9M)은
`단가 × 수량` 미보정으로 생긴 비현실적 값 — "한국 중소 수출기업" 설정과 배치된다.
→ **영향:** 라벨 정오와 무관. 렌더링 서류의 현실성 저하. **권고:** 금액을 30k~300k로 클램프.

### 이슈 2 — 회사명과 상품이 부정합 (systemic, 표본 다수)
예: CLEAN-018 "KOWON **ENERGY CELL** CO." 가 라면 수출 / DEFECT-005 "SEJIN **TEXTILE**"이
배터리 수출 / CLEAN-017 "NARAE **FOODS**"가 배터리 수출. 회사명 풀과 상품 풀이 독립 추첨되어
발생. → **영향:** UCP 하자 아님. 심사위원이 서류를 보면 눈에 띄는 어색함. **권고:** 회사명 풀을
산업에 바인딩(예: FOODS→식품 상품).

### 이슈 3 — DEFECT-011 신용장 내부 날짜 비정합
`latest_shipment_date(2026-05-21) < issue_date(2026-05-22)`. 신용장이 자기 발행일보다 이른
선적을 요구하는 모순. 지연제시 하자를 주입하며 날짜를 당길 때 `issue ≤ latest_shipment` 불변식이
깨진 것. → **영향:** 의도 하자(지연제시)는 성립하나 케이스가 비현실적. **권고:** 날짜 주입 시
`issue_date ≤ latest_shipment_date ≤ expiry` 불변식 보장.

### 이슈 4 — B/L 선적일이 L/C 발행일보다 이른 케이스 (DEFECT-011·012)
UCP600 14(i)상 서류가 신용장 발행일보다 이른 일자여도 수리 가능하므로 **하자는 아니다.** 다만
현실성 차원에서 정리 권고. 이슈 3 수정과 함께 해소됨.

## A 판단 항목 답: 벤치마크를 40건에서 늘릴 것인가

**권고 유지 — 40건 고정, 검수 품질에 투자.** 근거: (1) 현재 병목은 표본 수가 아니라 케이스
현실성(이슈 1~2)이다. 40건도 유형 커버리지는 충분(10유형×2 + 복합). (2) 늘리면 육안검수·교차검증
부담만 커지고 지표 신뢰도 상승폭은 작다. (3) 다양성이 목표라면 개수 확대보다 A-5(LLM 생성 5~10건
혼합)로 패턴 규칙성을 푸는 편이 효율적. 대신 이슈 1~3을 반영해 40건을 **재생성**(시드 유지 →
재현성 보존)하는 것을 D3 작업으로 제안한다.
