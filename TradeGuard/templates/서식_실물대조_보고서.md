# 서식 실물 대조 보고서 — 우리 템플릿 vs 실제 무역서류
> 2026-07-27 · 대조 기준: SWIFT ISO15022 MT700 공식 스펙, 실제 선사 B/L 양식, 수출 상업송장 관행

## 결론

**대조 전:** L/C에 **필수(Mandatory) 필드 `:40E: Applicable Rules`가 누락**돼 있었다. 이건 심각했다 —
UCP600 적용을 선언하는 바로 그 필드이고, 우리 서비스 전체가 UCP600 기반인데 그 근거 필드가 서류에
없었다. 무역금융을 아는 심사위원이라면 첫 화면에서 알아챈다.

**대조 후:** 누락 필드를 보완해 **MT700 필드 구성·순서가 공식 스펙과 일치**한다.
송장·B/L도 실무 필수 항목을 채웠다.

### 필드 순서 검증

렌더링 결과 실제 순서:
```
27 → 40A → 20 → 31C → 40E → 31D → 50 → 59 → 32B → (39A) → 41A → 42C → 42A
   → 43P → 43T → 44E → 44F → 44C → 45A → 46A → 47A → 71B → 48 → 49 → 78
```
**SWIFT 스펙 정의 순서와 완전 일치.** (선택 필드 생략분 제외)

### 남은 차이 (의도적)

- 실제 SWIFT 전문 헤더는 BIC 코드(`{1:F01...}`)를 쓰지만 우리는 은행명을 표기했다.
  → 데모에서 가독성이 낫고, 하자 판정에 BIC는 쓰이지 않는다.
- 필수가 아닌 선택 필드(23·51a·39B/C·42M/P·44A/B/D·53a·57a·72)는 생략했다.
  → 실제 L/C도 거래 성격에 따라 대부분 생략한다.

## 2. 상업송장 (Commercial Invoice)

| 항목 | 실무 | 대조 전 | 대조 후 |

| 송장번호·발행일 | 필수 | ✅ | ✅ |
| 매도인(수익자)·매수인(개설의뢰인) | 필수 | ✅ | ✅ |
| L/C 번호 참조 | L/C 거래 시 필수 | ✅ | ✅ |
| 상품명세·수량·단가·금액 | 필수 | ✅ | ✅ |
| 통화 | 필수 | ✅ | ✅ |
| Incoterms + 지정장소 | 필수 | ✅ | ✅ |
| 결제조건 | 필수 | ✅ | ✅ |

| **금액 문자표기 (SAY TOTAL)** | 관행상 필수 | ❌ 누락 | ✅ 추가 |
| 화인 (Shipping Marks & Nos.) | 필수 | ✅ | ✅ |

> 통관에도 필수 항목이라 실제 송장에 빠지는 일이 없다.

## 3. 선하증권 (Ocean Bill of Lading)

기준: [DHX 실제 Multimodal Ocean B/L 양식(PDF)](https://www.dhx.com/forms/DHX-Multimodal-Bill-of-Lading.pdf) ·
[Shipping & Freight Resource — B/L 구성요소](https://www.shippingandfreightresource.com/parts-of-a-bill-of-lading-part-3/)

| 항목 | 실제 양식 | 대조 전 | 대조 후 |
|---|---|---|---|
| Shipper / Consignee / Notify Party | ✅ | ✅ | ✅ |
| "not negotiable unless consigned to order" 문구 | ✅ | ❌ | ✅ 추가 |
| Vessel / Voyage | ✅ | ✅ | ✅ |
| Place of Receipt · Port of Loading · Port of Discharge · Place of Delivery | ✅ | ✅ | ✅ |
| **Booking No. / Export References** | ✅ | ❌ 누락 | ✅ 추가 |
| **Pre-carriage by** | ✅ | ❌ 누락 | ✅ 추가 |
| **Point and Country of Origin** | ✅ | ❌ 누락 | ✅ 추가 |
| **화물 명세 5열 테이블**<br>(Marks & Nos / No. of Pkgs / Description / Gross Weight / Measurement) | ✅ | ❌ **서술형 한 덩어리** | ✅ **표준 테이블로 교체** |
| Number of Originals | ✅ | ✅ | ✅ |
| Freight Prepaid/Collect | ✅ | ✅ | ✅ (Charges·Basis·Rate 라벨 추가) |
| Shipped on Board 부기/사전인쇄 | ✅ | ✅ | ✅ |
| Place and Date of Issue | ✅ | ✅ | ✅ |
| 서명 + 서명자 자격 | ✅ | ✅ | ✅ |
| 이면약관 참조 문언 | ✅ | ✅ | ✅ |

> **화물 명세를 5열 테이블로 바꾼 것이 가장 큰 개선이다.** 실제 B/L에서 이 영역은 예외 없이
> 컬럼 구조이고, 서술형 문단으로 보이면 실무자가 즉시 위화감을 느낀다.

## 데이터 무결성

템플릿에만 기본값을 넣고 **케이스 JSON·스키마·생성기는 건드리지 않았다.**
따라서:

- 벤치마크 40건 재현성 테스트 통과 (시드 고정 유지)
- 하자 검출 F1 1.000 유지
- 정답 라벨 변경 없음
- 통합 테스트 25/25 통과

새 필드는 데이터에 값이 있으면 그 값을, 없으면 실무 표준 문구를 표시한다.
A가 생성기를 보강하면 자동으로 개별 값이 채워진다.

> "SWIFT ISO15022 MT700 공식 스펙과 필드 단위로 대조했고, 필수 필드 `:40E: Applicable Rules`가
> 빠져 있던 것을 찾아 보완했습니다. 필드 구성과 순서가 스펙과 일치합니다.
> B/L은 실제 선사 양식과 대조해 화물 명세를 5열 표준 테이블로 맞췄습니다."

이 대조 작업 자체가 **"도메인을 실제로 공부했다"는 증거**가 된다. 기술설명서의 개발 과정에 넣을 것.

## 남은 보완 (선택)

- [ ] 생성기에 원산지·중량·포장수량 값 추가 (A) — 현재는 템플릿 기본값
- [ ] B/L 이면약관 1페이지 추가 — 실제 B/L은 앞뒤 2면. 데모 가치는 낮음
